# viewe-2.8-lvgl9-lottie

LVGL 9.5.0 port and Lottie animation test for the **Viewe UEDX24320028E-WB-A**
(2.8", 240x320 SPI TFT, capacitive touch, ESP32-S3 with PSRAM).
Built with PlatformIO and the Arduino framework.

> This repository is a source-only skeleton. LVGL itself is not included, see [Setup](#setup).

## What is included

| Path | Purpose |
| --- | --- |
| `platformio.ini` | Build config for the Viewe board |
| `lib/lv_conf.h` | LVGL 9.5 config with Lottie, ThorVG and vector graphics enabled |
| `src/main.cpp` | Board, LVGL and UI start-up |
| `src/esp_panel/` | Board config and the LVGL v9 display and touch port |
| `src/ui/` | EEZ Studio generated UI |
| `src/lottie/lottie_demo.*` | Creates the Lottie animation (currently the `lottie_school` array, 200x200, 60 fps) |
| `src/lottie/lottie_school.c` | The animation as a C array, generated by `tools/lottie_to_c.py` |
| `tools/lottie_check.py` | Checks a Lottie file and suggests a size |
| `tools/lottie_to_c.py` | Converts a `.json` or `.lottie` file to a C array |
| `animations/` | Source animation files |

## Setup

1. **Clone this repository.**

2. **Add LVGL 9.5.0 into `lib/lvgl-9.5.0`:**

   ```bash
   git clone --depth 1 --branch v9.5.0 https://github.com/lvgl/lvgl.git lib/lvgl-9.5.0
   ```

   Do **not** add `lvgl/lvgl` to `lib_deps`, or you will get two copies.

3. **Patch ThorVG to avoid a stack overflow.** In
   `lib/lvgl-9.5.0/src/libs/thorvg/tvgSwRle.cpp`, inside `rleRender`, change:

   ```cpp
   Cell buffer[RENDER_POOL_SIZE / sizeof(Cell)];
   ```

   to:

   ```cpp
   static Cell buffer[RENDER_POOL_SIZE / sizeof(Cell)];
   ```

   Without this, rendering needs about 19 KB of stack and the board reboots in a loop
   with a white screen. The change is safe because rendering is single threaded and
   runs under the LVGL lock.

4. **Check the stack sizes** (already set in this repository):
   - `LVGL_PORT_TASK_STACK_SIZE` is `24 * 1024` in `src/esp_panel/lvgl_v9_port.h`.
   - `SET_LOOP_TASK_STACK_SIZE(16 * 1024);` is at file level in `src/main.cpp`.

5. **Build and flash:**

   ```bash
   pio run -t clean
   pio run -t upload
   pio device monitor
   ```

## How the animation is started

In `src/main.cpp`, `setup()` calls `lottie_demo_create(objects.main);` after `ui_init();`,
with the LVGL lock held. The function in `src/lottie/lottie_demo.cpp`:

1. allocates a `LOTTIE_W * LOTTIE_H * 4` byte pixel buffer in PSRAM,
2. creates the widget and loads the array with `lv_lottie_set_src_data`,
3. sets the playback duration from `LOTTIE_FILE_FPS` and centers the animation.

The settings are the `#define` lines at the top of `lottie_demo.cpp`:

| Setting | Meaning |
| --- | --- |
| `LOTTIE_W`, `LOTTIE_H` | On-screen size in pixels. Keep the animation's aspect ratio. |
| `LOTTIE_FILE_FPS` | The file's own frame rate. LVGL assumes 60 fps, so a 30 fps file plays at double speed unless this is set. |
| `LOTTIE_BUF_CAPS` | Where the pixel buffer lives. PSRAM by default. |

## Using your own Lottie file

1. Put the file in `animations/`. It must be `.json` or `.lottie`.

2. Check its specs (fps, frame count, suggested size, and rendering warnings):

   ```bash
   python tools/lottie_to_c.py animations/my_anim.json
   ```

3. Convert it to a C array. The last argument is the symbol name used in the code
   (the demo currently uses `lottie_school`).

   **Linux / macOS:**

   ```bash
   python tools/lottie_to_c.py animations/my_anim.json lottie_school > src/lottie/lottie_school.c
   ```

   **Windows (PowerShell, preserves UTF-8 formatting):**

   ```powershell
   python tools/lottie_to_c.py animations/my_anim.json lottie_school | Out-File -FilePath src/lottie/lottie_school.c -Encoding utf8
   ```

4. In `src/lottie/lottie_demo.cpp`, make the symbol name match in three places: the two
   `extern` lines (`lottie_school` and `lottie_school_size`) and the
   `lv_lottie_set_src_data(...)` call. Then set `LOTTIE_W`, `LOTTIE_H` and
   `LOTTIE_FILE_FPS` for the new file, using the values from `lottie_check.py`.

5. Clean build and flash:

   ```bash
   pio run -t clean
   pio run -t upload
   ```

## Tips and troubleshooting

- **Start small** (around 120x120 pixels). ThorVG redraws the whole canvas every frame,
  so performance scales with total pixel count.
- The pixel buffer is allocated in PSRAM (`width * height * 4` bytes). The current
  200x200 size uses 160 KB.
- Set `LOTTIE_FILE_FPS` to the animation's true fps (from `lottie_check.py`) so it plays
  at the correct speed.
- **White screen and reboot loop:** check step 3 of [Setup](#setup) and the stack sizes.
- **Animation running too slow:** reduce `LOTTIE_W` and `LOTTIE_H` or simplify vector layers.
- Call `lottie_demo_report()` from `loop()` to print free heap, free PSRAM, and remaining
  LVGL task stack.
- **Changed `lv_conf.h`?** Run `pio run -t clean` before rebuilding.

## Notes

- Lottie usage here relies on LVGL 9.5's built-in `lv_lottie` widget with ThorVG, not the
  separate rlottie library.
- `-DLV_COLOR_16_SWAP=1` in `platformio.ini` is **mandatory** for this panel's SPI interface.
